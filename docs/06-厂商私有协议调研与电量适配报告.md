# 06 厂商私有协议调研与电量适配报告

> 版本：v2.0.0 · 覆盖目标硬件：英菲克 Inphic KP 8K、凌豹 K98PRO 5.0、漫步者 HECATE G5 Max

## 1. 背景与实测环境

在 Windows 11 真实宿主机测试中，原始 `hidapi` 裸枚举暴露出 3 个典型桌面外设工程问题：
1. **复合 HID 误判与重复列举**：电竞无线鼠标常同时声明 `Mouse (0x01:0x02)`、`Macro Keyboard (0x01:0x06)` 与 `Vendor Defined (0xFF00+)` 多个接口；裸遍历导致 `Inphic KP 8K (0x1D57:0xFA65)` 被误识别为键盘，而 `Sinowealth (0x258A:0x0040)` 被误判为鼠标且出现重复卡片。
2. **系统内置端点混入**：主板集成声卡（如 `Realtek 高清音频输出 (扬声器/耳麦)`）、显卡 HDMI 音频、精密触控板（ELAN/Synaptics）、USB Hub 均混在设备清单中。
3. **无协议电量与参数同步卡顿**：同步阻塞调用 `HidApi::new()` 与未防抖磁盘写入会导致拖滑块时 UI 卡死 1–2 秒。

## 2. 架构升级方案

### 2.1 Windows 原生蓝牙电量引擎（`src-tauri/src/win_battery.rs`）
- 直接通过 `#[link(name = "setupapi")]` 调用 Windows 原生 `SetupDiGetClassDevsW` + `SetupDiGetDevicePropertyW`，读取系统级属性 **`DEVPKEY_Bluetooth_Battery`**（GUID `{104EA319-6EE2-4701-BD47-8DDBF425BBE5}`, PID `2`）。
- 零外部依赖、不启动 PowerShell 子进程，单次全量查询耗时 **< 5 ms**。
- 可同时识别不带 HID 接口的蓝牙耳机（例如漫步者 HECATE G5 Max 蓝牙模式）并读取其 Windows 系统实时电量百分比。

### 2.2 复合 HID 聚合与系统端点黑名单（`src-tauri/src/vendor_protocols.rs`）
- 按 `(VID, PID)` 合并复合外设的所有 HID 接口：保留主设备类型判定（当同时存在鼠标与宏键盘接口时优先归类为鼠标，并优先匹配厂商指纹表），同时单独锁定 `Usage Page >= 0xFF00` 的私有控制通道路径 `vendor_control_path`。
- 系统端点过滤规则严格剔除：`Realtek`、`高清音频`、`扬声器`、`麦克风阵列`、`NVIDIA/AMD/Intel Display Audio`、`ELAN/Synaptics Touchpad`、`ACPI`、`Root Hub`、`Virtual Audio` 等内置/虚拟节点，同时白名单放行外接键鼠与耳机品牌。

### 2.3 全链路异步与防抖优化（彻底消除 1–2 秒卡顿）
- Rust 侧全部 Tauri Command（`scan_devices`、`refresh_device_battery`、`apply_*`、`save_portable_profile`）全部改为 `async fn` 并派发至 `tauri::async_runtime::spawn_blocking` 后台线程池，WebView2 主渲染线程零阻塞。
- HID 读取统一设置 `40ms` 短超时。
- 前端状态持久化防抖 `450ms`，硬件 HID 下发防抖 `120ms`。

## 3. 三款实测外设私有协议适配与可行性边界报告

| 设备型号 | 实测硬件指纹 / 通道 | 电量识别能力 | 参数直写可行性 | 工程处理策略与原因说明 |
| :--- | :--- | :--- | :--- | :--- |
| **英菲克 Inphic KP 8K** | `VID 0x1D57 / PID 0xFA65`（Beken / CompX 8K 方案，2.4G / USB） | **已实现（私有 HID 主动探测）**：锁定 `0xFF00` 接口下发 Beken 电量查询帧（Report ID `0x08` / Cmd `0x04`，40ms 超时），并在读不到时回退只读 Feature Report `0x04`。 | **部分实现（试验下发）**：已实现 Beken 17 字节回报率寄存器写帧（`125Hz–8000Hz` + 校验和）并通过锁定控制通道下发。 | Inphic 官方未公开完整寄存器手册，不同批次固件的 DPI 档位表偏移可能存在差异；如遇特定固件未响应，请以官方驱动为基准，LumenHID 保证不触发非法 Flash 擦写。 |
| **凌豹 K98PRO 5.0** | `VID 0x258A / PID 0x0040`（Sinowealth 中颖电子方案，固件上报字符串 `1.0.0`，蓝牙 5.0 / 2.4G / USB） | **已实现（蓝牙原生 + 只读 HID 双通道）**：蓝牙 5.0 模式直接读取 Windows `DEVPKEY_Bluetooth_Battery`；2.4G/USB 模式使用只读 `get_feature_report`（Report ID `0x04/0x05/0x06`）探测。 | **暂不开放盲写（安全只读）** | 1) 蓝牙 HOGP 协议在固件层仅开放标准键值与电量通道，不支持改键/灯效烧录；2) 中颖 `0x258A` 家族不同 PCB 的 Flash 键位映射页地址与校验算法各不相同，**在缺乏该型号专属 USB 抓包与固件校验表的情况下盲写存在变砖风险**。为保障用户键盘硬件绝对安全，仅开放识别、电量与本地配置保存。 |
| **漫步者 HECATE G5 Max** | 蓝牙 6.0 / 2.4G / USB 四模声学耳机 | **已实现（蓝牙原生实时电量）**：通过 `win_battery.rs` 直接在 Windows PnP 层发现 `HECATE G5 Max` 并读取 `DEVPKEY_Bluetooth_Battery` 电量。 | **板载 DSP 不可直写；提供 Windows 全局无损替代方案** | 漫步者 HECATE G5 Max 的板载 2.4G/USB DSP EQ 与 THX 空间音效采用闭源加密固件协议及官方专属 APO 驱动，第三方软件无法直接写入其耳机芯片寄存器。为此，LumenHID 在「音频与声场」模块内置了 **一键导出 EqualizerAPO 配置（`LumenHID-EQ.txt`）**，导入 EqualizerAPO 即可让任意 10 段 EQ 曲线对 G5 Max 的全通道系统音频实时生效。 |

## 4. 验证与回归清单

- 单元测试（`src/utils/deviceEngine.test.ts`）：验证 `Realtek 高清音频输出 (扬声器/耳麦)` 等系统端点被严格拦截；验证 `0x1D57:0xFA65`、`0x258A:0x0040`、`HECATE G5 Max` 指纹分类与 `EqualizerAPO` 导出格式正确。
- Rust 单元测试（`src-tauri/src/vendor_protocols.rs`、`win_battery.rs`）：验证硬件 ID `VID/PID` 解析、系统节点过滤与三款设备指纹表。
- Windows 实机验证：需通过 GitHub Actions `windows-latest` 重新编译最新 `LumenHID.exe` 后在宿主机验证实时电量与图标挂载。
